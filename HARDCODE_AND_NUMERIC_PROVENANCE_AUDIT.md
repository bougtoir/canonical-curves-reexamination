# Hardcode and numeric provenance audit (JCPA)

## Method

- Grepped `text_jcpa.py` for numeric literals: only years, citation years,
  counts written as words, and `{placeholder}` tokens — no result values.
- Inspected `build_manuscript.py` jcpa branches (`table_data`, `plot_figures`,
  `COVER_LETTER_BODY`, `JOURNAL_META`): the comparative Table 5 and Figure 1
  contain only qualitative text; no numeric literals.
- `numbers.json` is generated by `build_manuscript.py` from canonical
  files and is the only injection point; `check_manuscript.py`
  independently re-derives six headline values from the CSVs.
- Compared `numbers.json` values against `results/`, `fukushima/results/`,
  `kansas/results/` canonical files.

## Classification of material values (summary; see numeric_claim_registry.csv)

- GENERATED: all DiD/SC estimates, p-values, decomposition counts, mapping
  counts and shares — 88 registry claims verified to canonical files.
- DERIVED FROM GENERATED OUTPUT: percentage renderings (e.g. att → 8%),
  cumulative-gap rounding, share ranges.
- EXTERNAL FIXED FACT: ra_related_deaths (Reconstruction Agency release),
  thj_* (Ten Hoeve & Jacobson published estimates), fdr_no/year,
  evac_pop_approx, ks_pre_years — cited, not computed.
- LEGITIMATE CONFIGURATION CONSTANT: alpha_default 0.05, k_default 3,
  tsunami_cut 1.2%, sc_age_band 10pp, n_perm 1000, grids.
- MANUAL/HARDCODED — REQUIRES REMEDIATION: none found.
- UNRESOLVED: none.

## Findings

- No scientific result is manually asserted in text, tables, figures, or
  captions; every numeric placeholder resolves to a canonical output.
- Table 5 (comparative summary) is intentionally qualitative; its cells
  mirror case-section claims, not results files.
- One stale literal removed earlier this audit chain: none remains.
